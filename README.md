# The Tableau Repo

**[thetableaurepo.com](https://thetableaurepo.com)**: Tableau data visualization tips & principles.

A static website that collects the best free Tableau writing in one place:

| Section | What it holds | Pages |
|---|---|---|
| **Articles** | 160 hand-picked articles, organised by the categories and subcategories of the research guide *Tableau Mastery & Data Consultancy Careers*. Articles the guide lists more than once appear on every topic they belong to. | `/articles/` → category → subcategory |
| **Visualizations** | Most-favourited Tableau Public vizzes from 10 experts (Andy Kriebel, Ryan Sleeper, Shreya Arya, Eve Thomas, Lorna Brown, Bethany Lyons, Scott Foster, Ken & Kevin Flerlage, Jonathan Drummey), each linked to their Tableau Public profile. | `/visualizations/` → author |
| **Short quotes** | 101 memorable lines quoted word for word from the articles, arranged by the same categories. | `/quotes/` → category |

The site **links** to articles and vizzes. It never copies them: every card points to the original, and quotes are short, attributed excerpts.

---

## Quick start

Requires [Node.js](https://nodejs.org) 20 or newer.

```bash
npm install        # once
npm start          # preview at http://localhost:8080 (reloads as you edit)
npm run build      # build the finished site into _site/
npm test           # run the automated checks
```

## How the project is organised

```
content/              ← ALL the words and data. Edit these to change the site.
  site.yaml             site name, address, tagline, footer note
  categories.yaml       the topic tree (categories → subcategories → sections, takeaways)
  articles.yaml         every article, and the topics it is placed on
  quotes.yaml           short quotes, each tied to an article
  people.yaml           featured experts (Visualizations pages)
  vizzes.json           generated by `npm run fetch:vizzes`; don't edit by hand

lib/                  ← reusable JavaScript (no web access, easy to test)
  load-content.js       reads the files in content/
  catalog.js            shapes content into page data + the menu; URL scheme
  validate.js           finds mistakes in content (missing fields, bad links between files)
  text.js               text helpers used to check quotes
  http.js               network helpers used by the scripts

scripts/              ← maintenance commands (see below)
src/                  ← the website templates (Eleventy + Nunjucks)
  _data/catalog.js      exposes lib/catalog.js to templates as `catalog`
  _includes/layouts/    page shell (head, header, footer)
  _includes/partials/   header, hover menu, footer
  _includes/macros/     reusable components: cards, page header, callout…
  index.njk             home page
  articles/             articles index, category pages, subcategory pages
  quotes/               quotes index and category pages
  visualizations/       authors index and author pages
  assets/               CSS, JavaScript (menu.js) and the favicon
tests/                ← automated checks (`npm test`)
eleventy.config.js    ← build settings and template filters
.github/workflows/    ← build, test and deploy to GitHub Pages
```

Every file starts with a comment explaining what it does, and every function documents what it returns and when to call it.

## Everyday editing

All changes happen in `content/`. After any edit, run `npm run validate`: it tells you exactly what to fix. The build runs the same checks and refuses to publish broken content.

### Add an article

Add an entry to `content/articles.yaml`:

```yaml
- id: kriebel-new-post                # unique; lowercase-with-hyphens
  title: The title as published
  authors: [Andy Kriebel]             # same spelling as people.yaml → name links to their page
  publisher: VizWiz
  url: https://www.vizwiz.com/...
  published: 2026-10-01               # optional: YYYY, YYYY-MM or YYYY-MM-DD
  summary: One or two sentences in your own words.
  placements:                         # every topic the article belongs to
    - topic: visualization/best-practices
    - topic: tableau-basics/basic-charting
      note: Optional line explaining why it's here.
```

Topic names are `category-slug/subcategory-slug` from `categories.yaml` (or just `miscellaneous`). Use `section:` to put an article under one of a subcategory's sections, such as `partitioning-vs-addressing`.

### Add a quote

```yaml
- text: The exact words from the article.
  author: Andy Kriebel
  article: kriebel-new-post           # the article's id
  topic: visualization/best-practices # optional; defaults to the article's first topic
```

Then run `npm run verify:quotes` to confirm the words appear verbatim in the source.

### Add an expert to Visualizations

1. Add them to `content/people.yaml` (slug, name, Tableau Public profile URL, short bio).
2. Run `npm run fetch:vizzes -- --only their-slug` to download their most-favourited vizzes.

### Add a category or subcategory

Add it to `content/categories.yaml`. Pages, menu entries and breadcrumbs are generated automatically.

## Maintenance commands

| Command | What it does | When |
|---|---|---|
| `npm run validate` | Checks content files for mistakes (offline). | After every edit |
| `npm test` | Runs the automated tests. | Before committing |
| `npm run check:links` | Checks every article and profile URL still works. | Every few months |
| `npm run verify:quotes` | Re-checks every quote against its live article. | After adding quotes; every few months |
| `npm run fetch:vizzes` | Refreshes viz galleries from Tableau Public. | After adding a person; every few months |

The last three use the internet. Behind a corporate proxy, prefix them with `NODE_USE_ENV_PROXY=1`. Some sources are PDFs or pages drawn by JavaScript, which the quote checker can't read; it lists those as "not checked" so you can check them by hand.

## Publishing to thetableaurepo.com

The workflow in `.github/workflows/deploy.yml` tests and builds every push, and publishes the `main` branch to GitHub Pages. Other branches are built and tested but never published.

One-time setup:

1. **GitHub**: merge the site into a `main` branch (and make it the default branch under *Settings → General*), then go to *Settings → Pages → Build and deployment → Source: GitHub Actions*. The custom domain comes from `src/CNAME`. Tick **Enforce HTTPS** once the certificate is issued.
2. **DNS** at your domain registrar:
   - `A` records for `thetableaurepo.com` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `CNAME` record for `www` → `<your-github-user>.github.io`

## Design notes

- **Menu**: hidden behind the *Menu* button. On a desktop, hovering it reveals Home, Articles, Visualizations and Short quotes, and hovering an entry with sub-pages opens a fly-out listing them (Articles → categories → subcategories). On touch screens the button opens a full-screen menu with expandable sections. Keyboard users get the same via Tab and Escape.
- **Colour**: each category has an accent from a colour-blind-checked palette, validated in light and dark mode. Colours mark things (stripes, bars) and are never the only way to tell categories apart.
- **Dark mode** follows the visitor's system setting.
- **No tracking, no client-side framework**: pages are plain HTML and CSS with one small script for the menu.
